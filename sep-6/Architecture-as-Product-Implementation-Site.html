The Combined Vision
Where We Are & Where We're Going
GPB must resolve the fundamental tension between functional domains (organized by human workflow) and data domains (organized by data itself) -- while simultaneously building the platform that makes architecture consumable.

Current State

  • Bespoke solutions -- project mindset, duplication
  • Pipeline sprawl -- custom HA, manual envs, idle infra
  • Standards as documents -- inconsistent interpretation
  • Functional domains by org chart -- 20+ areas, hundreds of systems
  • Data & functional architectures misaligned
  • 1,110 datasets but not harmonized into products
  • Reliability assumed, not proven
  • SBOMs stop at awareness -- no automated action
  • AI agents can't operate -- no semantic layer
→

Target State

  • Platform mindset -- solve once, reuse always
  • Automated governance -- policy-as-code
  • Capabilities as code -- not documents
  • Unified vertical ownership -- 5 verticals, data-first
  • AI-ready Data Products -- governed, self-describing
  • Semantic layer -- glossary, ontology, skills catalog
  • Reliability proven under stress via chaos engineering
  • Self-correcting systems -- detect & fix autonomously
  • Human + AI agents -- same delivery interface

The functional domain map is like a city built neighborhood by neighborhood, each with its own water supply, electrical grid, and road system. It works -- until you need a highway or a regional power grid.

WS 2Event-Driven Architecture & Semantic Integration
Rewire integration to event-driven semantics, separating business facts from system behavior -- and build the semantic layer that enables AI agents to reason across data domains.

Event Taxonomy

Roman Events (Business Facts)

Durable, immutable records: party.created, account.opened, relationship.established. Each vertical owns its facts.

Canonical Events (System Behavior)

Reactions enabling interoperability: client-profile-synchronized, onboarding-screening-requested

Control Plane Components

  • Source Repo Definitions -- schemas, ownership, versions in Git
  • CI Validation Skill -- validates, registers, quarantines
  • EventCatalog -- discoverability & governance
  • Governance Engine -- policy evaluation & enforcement

Semantic Layer & Knowledge Bases NEW

Business Glossary

Single authoritative definitions for "client", "account", "position" across all 5 verticals.

Metadata + Ontology

Provenance, quality scores, access controls. Machine-readable domain model for agent navigation.

Skills/Tools Catalog

Typed, permissioned: inputs/outputs, entitlements, risk tags, versioning, ownership.

Unstructured Knowledge Layer

Vectorized policies, documents, rules, decision history. Skill playbooks made RAG-accessible.

WS 3Composable Cloud Environments
Move from handcrafted, team-specific environments to composable, standardized environment assembly -- with replay-driven cost reduction.

Environment Composition Model

1. Application Pattern what type of workload
2. Environment Profile dev, staging, production
3. Resilience Profile Standard to Mission Critical
4. Deployment Strategy canary, blue/green, rolling
5. Running Environment provisioned infrastructure

Same inputs always produce same outcomes. Environment-as-Code generates VPC, CI/CD, IAM, Observability.

Replay-Driven Reduction NEW

Phase 1: Record

Capture real production behavior. Convert into reusable test artifacts in a Central Behavioral Asset Repository.

Phase 2: Replay

Replace always-on dependent systems with lightweight replay proxies. Only the system-under-test is active.

Cloud Cost Transformation

From topology-driven (persistent infra, high cost) to usage-driven (ephemeral, on-demand, cost aligned to usage).

We don't need environments to validate systems. We need behavior.

WS 4AI-Native Software Delivery Platform
Rethink CI/CD from pipelines-per-team to a platform-owned delivery control plane that supports human and AI agent velocity.

Core: Decouple Integration from Release

Merge = Integration Event
→
Candidate Build = Platform Decision
→
Release = Artifact Promotion

Enterprise Delivery Broker

  • Accepts input from Git, CLI, and AI Agents
  • App Metadata Catalog -- class, runtime, env model, compliance
  • Merge Queue -- trunk admission, compatibility validation
  • Candidate Cut Policy -- time-window batching, thresholds
  • Release Set + Artifact Lineage -- immutable, SBOM-tracked

Intent-Driven Delivery

runtime: java21 service: advisor-portal deploy: environment: dev strategy: blue-green

AI-Native Delivery Flow

Preview -- Feature Speed

Isolated validation, ephemeral environments, agent + human feedback

Integrate -- Integration Speed

Controlled trunk admission, incremental verification

Release Set -- Decision Layer

Grouped change intent, policy-driven candidate cut

Artifact + Promotion -- Release Speed

Build once, promote many, immutable lineage

SBOM Autonomous Remediation NEW

  • SBOM as Trigger -- Detection > Policy > Automated Action
  • Policy Engine -- no critical CVEs, runtime N-1, license check
  • Remediation Loop -- SBOM > Policy > Agent > PR > CI > Verified
  • Autonomy Inside Guardrails -- auto-fix within boundaries

Transform the architect role from document reviewers to product builders -- and merge functional and data architect roles into AI-Native Enterprise Architects.

ArtifactsUI wireframes, process flowsER diagrams, data modelsOntologies, agent workflows, data contracts, MCP interfaces, KBs, Skills

The era of the architect who only knows one application is ending and the era of the data architect who only draws ER diagrams is also ending. What we need are architects who can think across all three pillars: data, functional/process, and AI.

Execution
4-Wave Roadmap
12 months from foundation to scale across all 7 workstreams.

Wave 1: Foundation

Months 1-3
  • Inventory existing patterns across GPB teams
  • Define 6 core patterns + data domain alignment
  • Establish fact vs. behavior event taxonomy
  • Define 4 reliability tiers
  • Design .platform/deploy.yaml intent spec
  • Align architects on converged role
  • Appoint Data Executives for all 5 verticals
  • Begin business glossary -- cross-vertical terms
  • Define chaos primitives & scenario library
  • Assess SBOM coverage & define policy rules

Wave 2: Build

Months 3-6
  • Build Pattern Catalog UI
  • Build Event Architecture Control Plane
  • Build Environment Composition platform
  • Build Enterprise Delivery Broker v1
  • Build executable Reliability Profiles
  • Implement policy-as-code in CI pipelines
  • Core Data Products per vertical
  • Semantic Layer v1 (glossary, metadata, ontology)
  • Chaos Engineering platform capability
  • Phase 1 Replay: record production behavior
  • Build SBOM intelligence layer & policy engine

Wave 3: Adopt

Months 6-9
  • Onboard 3 pilot teams to pattern catalog
  • Onboard 3 pilot teams to delivery platform
  • Deploy preview environments
  • Publish Core Data Products to marketplace
  • Build Analytical Data Products (Performance Insights, Client 360)
  • Phase 2 Replay: replace envs with proxies
  • Continuous chaos validation in CI/CD
  • Autonomous SBOM remediation (low-risk)
  • Measure adoption metrics
  • Collect feedback, iterate

Wave 4: Scale

Months 9-12
  • Roll out to all GPB teams
  • Enable AI agent delivery path
  • Full EventCatalog + dependency visualization
  • Platform-managed pipelines for all
  • Decommission custom CI/CD configurations
  • Complete Core Data Products all verticals
  • Cross-vertical AI-native queries
  • Semantic Layer v2 (full ontology, skills, KBs)
  • Replay-driven env cost reduction
  • Chaos validation all Critical+ services
  • Full autonomous SBOM remediation loop
  • All architects in converged model
